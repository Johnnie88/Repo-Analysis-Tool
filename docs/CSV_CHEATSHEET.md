# CSV Output Cheatsheet — Repository Intelligence CLI Tool (v3.0.0)

This document provides a complete reference for all CSV columns generated by the tool across both output files:
- **`summary_all.csv`** — Full technical dataset (40+ columns)
- **`summary_metadata.csv`** — Curated executive summary (15 columns)

---

##  `summary_all.csv` — Complete Column Reference

| Column | Type | Description | Source / Stage |
|--------|------|-------------|----------------|
| **Repository Identity** |
| `repo_name` | string | Repository/folder name | Stage 1 (Structure) |
| `is_git` | bool | True if `.git` folder exists with valid history | Stage 0 (Git Meta) |
| `license_type` | string | Detected license (MIT, Apache-2.0, GPL, etc.) or `Unknown` | Stage 4 (Intelligence) |
| **Git Metadata & Timeline** |
| `first_commit_date` | ISO8601 | Timestamp of first commit | Stage 0 |
| `last_commit_date` | ISO8601 | Timestamp of most recent commit | Stage 0 |
| `development_span_months` | int | Active lifespan in months (first → last commit) | Stage 0 |
| `commits` | int | Total commits on default branch | Stage 0 |
| `meaningful_commit_count` | int | Commits excluding generic/boilerplate messages | Stage 0 |
| `commits_per_month` | float | Average commit velocity per active month | Stage 0 |
| `branch_count` | int | Total local branches discovered | Stage 0 |
| `git_history_intact` | bool | History appears continuous (no suspicious bulk/squash) | Stage 0 |
| **Contributors** |
| `contributors` | int | Unique contributor emails from Git history | Stage 0 |
| `all_contributors_count` | int | Total identities (names + emails combined) | Stage 0 |
| `all_contributors` | string | Pipe-separated list of contributor names (truncated in CLI) | Stage 0 |
| **Code Size & Tokens** |
| `loc_code` | int | Lines of executable code (via `cloc`) | Stage 1/2 (cloc) |
| `loc_comment` | int | Comment/docstring lines | Stage 1/2 |
| `loc_blank` | int | Blank lines | Stage 1/2 |
| `loc_files` | int | Total source files analyzed | Stage 1/2 |
| `tokens_llm` | int | LLM token count (cl100k_base / GPT-4 tokenizer) | Stage 2 |
| `lexical_token` | int | Raw symbol/identifier/operator count | Stage 2 |
| **Languages** |
| `lang_count` | int | Distinct programming languages detected | Stage 1/2 |
| `languages` | string | Pipe-separated: `Language:bytes%` (e.g., `Python:65%|JavaScript:20%`) | Stage 1/2 |
| `languages_frontend` | string | Frontend languages subset (HTML, CSS, JS, TS, Vue, Svelte) | Stage 4 |
| `languages_backend` | string | Backend languages subset (Python, Go, Java, Rust, etc.) | Stage 4 |
| `languages_percentage_bytes_gt5` | string | Languages >5% of repo size: `Lang:XX%` | Stage 4 |
| **Frameworks** |
| `frameworks` | string | Detailed framework map: `source:framework1,framework2` | Stage 1/4 |
| `framework_frontend` | string | High-level frontend frameworks (React, Vue, Next.js, etc.) | Stage 4 |
| `framework_backend` | string | High-level backend frameworks (Django, Express, FastAPI, Spring) | Stage 4 |
| `frameworks_percentage_bytes_gt5` | string | Frameworks >5% of associated code: `Fwk:XX%` | Stage 4 |
| **Infrastructure & Integrations** |
| `databases_used` | string | Detected DBs: PostgreSQL, Redis, MongoDB, MySQL, etc. | Stage 4 |
| `third_party_apis` | string | External SaaS: Stripe, Twilio, Firebase, OpenAI, etc. | Stage 4 |
| `setup_guidelines` | enum | `Present` / `Not found` — setup/install docs detected | Stage 4 |
| **Security, Quality & Heuristics** |
| `security_findings` | string | `Clean` or `Review Required (N)` — secrets detected | Stage 5 |
| `documentation_quality` | enum | `High` / `Medium` / `Low` — README depth & structure | Stage 4 |
| `duplication_weighted_percent` | float | Duplicated code % weighted by token size | Stage 2 |
| `code_complexity` | enum | `Low` / `Moderate` / `High` — file length, nesting, variance | Stage 2/3 |
| `ai_detection_percent` | float | Experimental: probability of AI-generated code segments | Stage 3 |
| `repo_rating_score` | float | Composite score 0–10 (see `RATING_CRITERIA`) | Stage 4 |
| `repo_rating_label` | enum | `Poor` / `Fair` / `Good` / `Excellent` | Stage 4 |
| **Process Metrics** |
| `total_time_seconds` | float | Pipeline execution time for this repo | All stages |
| **GitHub PR Analytics (Stage 0.5 — requires `GITHUB_TOKEN`)** |
| `total_pr_count` | int | Total Pull Requests (all states) | GitHub API |
| `open_pr_count` | int | Currently open PRs | GitHub API |
| `closed_pr_count` | int | Closed PRs (merged + abandoned) | GitHub API |
| `merged_pr_count` | int | Successfully merged PRs (subset of closed) | GitHub API |
| `github_pr_analysis_available` | bool | True if PR analytics ran successfully | Stage 0.5 |

##  Rating Criteria (`repo_rating_score`)

| Metric | Weight | Min Threshold | Preferred |
|--------|--------|---------------|-----------|
| Commits | 20% | 75 | 200 |
| Dev span (months) | 15% | 6 | 24 |
| Contributors | 15% | 2 | 5 |
| Lines of Code | 20% | 5,000 | 50,000 |
| Has Tests | 10% | — | Yes |
| Has CI | 10% | — | Yes |
| Test file count | 5% | 20 | 200 |
| Source file ratio | 5% | 0.40 | 0.60 |

**Labels:**
- `≥ 8.0` → **Excellent**
- `≥ 6.0` → **Good**
- `≥ 4.0` → **Fair**
- `< 4.0` → **Poor**

##  Key Derived Fields Explained

| Field | How It's Computed |
|-------|-------------------|
| `languages_frontend` / `backend` | Mapped from `FRONTEND_LANGUAGES` / `BACKEND_LANGUAGES` sets |
| `framework_frontend` / `backend` | Mapped from `FRONTEND_FRAMEWORKS` / `BACKEND_FRAMEWORKS` sets |
| `duplication_weighted_percent` | Sum of tokens in duplicate clusters / total tokens |
| `code_complexity` | Heuristic: avg file LOC, line length variance, nested depth samples |
| `ai_detection_percent` | Entropy + token uniformity across files (experimental) |
| `security_findings` | Regex scan for 12 secret patterns (AWS, GitHub, Stripe, keys, etc.) |

##  Usage Tips

```bash
# View full dataset
csvcut -n outputs/summary_all.csv

# Filter high-rated repos
csvgrep -c repo_rating_score -r '^[7-9]\.' outputs/summary_all.csv

# Quick stats
csvstat outputs/summary_all.csv --cols repo_rating_score,loc_code,commits

# Merge with metadata
csvjoin -c repo_name outputs/summary_all.csv outputs/summary_metadata.csv
```

